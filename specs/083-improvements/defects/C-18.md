# C-18 — CHUNK_MAX_RETRIES=0 means zero attempts

> **Priority**: P1  
> **Audit status**: FIXED  
> **Cluster**: [`04-pipeline-reliability`](../clusters/04-pipeline-reliability/)  
> **Sprint**: 2  
> **Laws**: LAW-3  
> **Cross-refs**: X-06

---

## 1. WHY

Chunks skipped silently with no error when env set to 0.

---

## 2. Audit (code is law)

| Field | Value |
|-------|-------|
| Primary locus | `pipeline/extraction.rs:302; config allows 0` |
| Verdict | **FIXED** |
| Verified against | HEAD audit 2026-07-23 (v0.20.2 lineage) |

---

## 3. Root cause (first principles)

for attempt in 1..=max_retries empty when 0; name says retries not attempts.

---

## 4. ASCII causal diagram

```

  max_retries=0 --> 1..=0 --> no loop --> no extract, no error
```

---

## 5. Solution (SOLID + DRY)

Rename to max_attempts with min 1, OR treat 0 as 1 attempt; reject invalid config at boot.

| Principle | Application |
|-----------|-------------|
| S | Own the invariant in one module named in the solution |
| D | Depend on SSOT helpers (SchemaReadiness, TenantContext, RetryExecutor, TokenEstimator, …) |
| DRY | No second copy of normalize / retry / GUC / score scale |

---

## 6. Edge cases

fail-fast tests expecting 0
