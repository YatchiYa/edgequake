---

## 1. WHY

Absence of eq_* columns or NULL backfill silently breaks degree/incident-edge queries or excludes rows — production chat failure mode.

---

| Field | Value |

---

## 3. Root cause (first principles)

Readers bound exclusively to denormalized columns without catalog probe or property-path fallback. Prefix scans with IS NOT NULL drop non-backfilled edges.

---

## 4. ASCII causal diagram

```

  read_path --> eq_source_id IN (...)
       |              |
       |         column missing --> SQL ERROR
       |         NULL eq_* --> silent miss
       v
  no COALESCE(props->>'source_id')
```

---

## 5. Solution (SOLID + DRY)

SchemaReadiness probe; dual SQL path (eq_* vs props); never filter out NULL eq_* without property OR; metric when fallback used.

| Principle | Application |
|-----------|-------------|
| S | Own the invariant in one module named in the solution |
| D | Depend on SSOT helpers (SchemaReadiness, TenantContext, RetryExecutor, TokenEstimator, …) |
| DRY | No second copy of normalize / retry / GUC / score scale |

---

## 6. Edge cases

column missing vs NULL; mixed backfill; empty node_ids
